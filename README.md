# AI presentation tool

**Google ドキュメントの URL を貼るだけ**、または Markdown を入力すると、
見出しごとに1枚のスライド画像を **GPT Image 2.0** で生成し、
PPTX として書き出す3ペインのデスクトップツール（Flask）。

`premovie-4pines` のスライド生成エンジンを汎用化して構築。

## 3ペイン構成

| ペイン | 役割 |
|--------|------|
| 1 プロジェクト管理 | 一覧／`＋`新規作成（ドキュメントURL・Markdown・デザインプロンプト・見本画像） |
| 2 台本編集 | ドキュメント取り込み／Markdown を編集 →「スライド生成」 |
| 3 プレビュー | 各スライド表示／キーワード確認／修正入力＋個別再生成／一括再生成／PPTX書き出し |

## 入力の2つの方法

### ① Google ドキュメントを取り込む

新規作成時に URL を貼るか、ペイン2の入力欄に URL を入れて「取り込み」を押す。

- **共有設定を「リンクを知っている全員（閲覧者）」にしておく**こと。
  非公開のままだと読み取れない（そのときはエラーで案内が出る）。
- 認証なしで docx としてエクスポートして読むため、GCP や OAuth の設定は不要。
- 非公開のまま使いたい場合は、ドキュメントを
  「ファイル → ダウンロード → Microsoft Word (.docx)」で保存し、
  ペイン2の「.docx」ボタンからアップロードする。

取り込むと、以下が Markdown に正規化されて `markdown.md` に保存される。

| ドキュメントの要素 | 変換先 |
|--------------------|--------|
| 見出し1〜3 | `#` `##` `###`（＝スライドの区切り） |
| 見出し4以降・本文 | 段落テキスト（直近スライドの本文） |
| 箇条書き・番号付きリスト | `- ` の箇条書き |
| 表 | 1行ずつ `- セル / セル` の箇条書き |
| 画像 | `_doc/img_NNN.png` に保存し `![](_doc/img_000.png)` で参照 |

取り込み後の Markdown はそのまま編集できる。画像がどのスライドに載るかは
**Markdown 上の `![]()` の位置（直前の見出し）**で決まるので、
行を移動させれば画像の割り当ても変わる。

### ② Markdown を直接書く

従来どおり、ペイン2に Markdown を書いてもよい。

## スライド分割ルール

- 見出し1/2/3（`#` `##` `###`）**ごとに1スライド**
- 見出し4以降・箇条書き・段落は直近スライドの本文にまとまる
- 画像参照は直近スライドの「使用したい画像」として添付される
  （1スライドあたり16枚まで。これは画像生成APIが一度に受け取れる上限で、
  見本デザイン画像もこの枚数に含まれる）

## 画像の扱い

- **切り取らない**: 渡した画像は全体をそのまま使う。「重要そうな部分を切り出す」
  「拡大して寄せる」「縦横比を変える」はいずれも禁止するようプロンプトで指示している。
  ドキュメントに貼る時点でトリミング済みの画像を、さらに切られないようにするため。
- **文脈を保つ**: ドキュメント上で画像が本文のどの位置に挟まれていたかを
  `plan.json` の `content` に順序ごと保持し、
  「画像1は『〜』の説明に対応」というメモ（`image_notes`）を要約時に生成する。
  画像生成では添付順を「画像1」「画像2」…と対応づけて渡すので、
  各画像が関連するキーワードの隣に配置される。
- **大きく使う**: 全体でスライド面積の3〜5割を目安に主役として配置させる。

## 解剖図をライブラリから選ぶ

医学系のスライドで解剖図が要るとき、購入済みの共有ライブラリ
`~/src/medical-image-library`（390枚）から選んでスライドの素材にできる。
ペイン3の各スライドにある **「図」ボタン**から、キーワード・部位・種別で絞って選ぶ。
選んだ図はプロジェクトに素材画像としてコピーされるので、以降は自分で
アップロードした素材とまったく同じ扱いになる（削除も生成時の添付も同じ経路）。

絞り込みは**「画像内に文字なし」を既定ONにしてある**。ライブラリには英語ラベルが
焼き込まれた図が43枚あり、日本語スライドに混ぜると事故りやすいため。

参照先は環境変数 `MEDICAL_IMAGE_LIBRARY` で差し替えられる。ライブラリが無い環境では
「図」ボタンが出ないだけで、他の機能はそのまま動く。画像はこのリポジトリにコピーしない。

**限界**: 生成には `images.edit` を使っており、**モデルは渡した画像を必ず描き直す**。
つまりライブラリの図をそのまま渡しても、ピクセル単位の無改変は保証できない。
構図や雰囲気の指定としては効くが、**細部の解剖学的な正確さが要る図は、
書き出した PPTX 側で元画像に差し替える**のが確実。

## 本文の要約（キーワード化）

ドキュメントの本文をそのまま描かせると文字量が多すぎて読めないため、
「キーワードに要約」（既定ON）でテキストLLMが各スライドを次の形に絞り込む。

- **keywords**: スライドに大きく描く 3〜6 個の短いキーワード・数字
- **illustration**: 内容を直感的に伝える図解・イラストの指示
- **image_notes**: 画像1枚ごとに「何を示している画像か・どのキーワードの近くに置くか」

数値・固有名詞は変えずに残し、そのスライドに画像がある場合は
「画像が主役」になるよう図解を控えめにする。結果はペイン3のカードに
チップとして表示されるので、生成前に中身を確認できる。

要約をOFFにすると、従来どおり本文をそのまま素材として渡し、
絞り込みは画像生成モデル側に任せる。

## 最後のスライドは一次ソースの引用リスト

**どのテンプレートでも、発表の最後は「よく分からないまとめ」ではなく
一次ソースの引用リストで終える。** 聞いた人がその論文に確実にたどり着けるよう、
1件1行で**特定できる情報**を並べる。

| 項目 | 例 |
|------|-----|
| ナンバリング | `1.` |
| 著者名（1人＋`et al.` で十分） | `M. Enger et al.,` |
| 雑誌名 | `BMC Musculoskelet. Disord.` |
| 巻（号）・ページ・年 | `26, 546 (2025).` |

論文以外の一次ソース（書籍・ガイドライン・公的統計など）は、それに類する情報でよい。

### 台本の書き方

台本の末尾に **「引用文献」「参考文献」「出典」「References」** などの見出しを作り、
その下に1行1件で書く。

```
# 引用文献
1／R. L. Diercks, M. Stevens, J. Shoulder Elbow Surg. 13, 499–502 (2004).
2／M. Enger et al., BMC Musculoskelet. Disord. 26, 546 (2025).
```

### 徹底のしかた（自動でやること）

- **必ず末尾に回す**。台本が「引用文献 → まとめ」の順でも、構成案では引用文献が
  最後になる（文献スライド同士の順序は変えない）。
- **要約しない**。この見出しのスライドだけは要約層も画像生成側の「キーワード中心」
  ルールも通さず、1件1行でそのまま列挙する。文献は番号・著者・雑誌名・巻・号・
  ページ・年がそろって初めて引用として成立するので、キーワードにまとめた時点で
  引用ではなくなるため。
- **足りない項目を名指しする**。各行を後ろから「年 →巻（号）・ページ →著者名・雑誌名」
  と照合し、欠けているものをペイン3のその行に出す（`reference_field_gaps`）。
  **足りない情報をAIに補わせることはしない**。存在しない文献ができあがるため、
  直すのは台本側。
- **引用リストが無いまま終わらせない**。引用文献スライドが1枚も無いとペイン3の
  上部に警告が出続け、PPTX 書き出し時にも確認を挟む（`reference_check`）。

### その他の挙動

- 台本の1行が `13／T. Holmgren et al., BMJ 344, e787 (2012).／https://... ／論文要約：…`
  のように区切られている場合、**スライドに載せるのは書誌情報のところだけ**。
  URL や論文要約・引用理由のメモは発表者向けなので落とす（ノートには原文が残る）。
- **文献番号は台本のものをそのまま使う**。他のスライドから「文献12」と参照されるため、
  振り直さない。番号が無い行には通し番号を振る。
- 1枚に載せるのは最大 14 件（`MAX_REFERENCES_PER_SLIDE`）。超える場合は
  「引用文献（1/2）」のように**均等に分割**する。要約しない＝件数がそのまま行数なので、
  分けないと文字が潰れるため。
- デザイン（配色・装飾）はテンプレートに従うが、文字量・レイアウトのルールは
  このスライド専用のものが優先される。**小さい文字を許可**し、装飾は右側の
  小さなイラスト程度に留めさせる。
- ペイン3のカードには、実際に載る行が全部そのまま表示される。

## 発表用ノート

スライドに描かれるのは要約されたキーワードだけなので、**そのままでは発表時に
何を話すかが分からない**。そこで PPTX 書き出し時に、各スライドの
**ノート欄（スピーカーノート）へ、そのスライドの元になった台本をそのまま入れる**。
ペイン3の「ノートに台本を入れる」で切り替えられる（**既定ON**、プロジェクトごとに記憶）。

- 見出し1/2/3ごとにスライドを分けているので、**どの台本がどのスライドに対応するかは
  分割時点で確定している**。対応付けにAIを使わないため、ずれも追加のAPI呼び出しも発生しない。
- 台本は**原文のまま**入る。箇条書きの `- ` や番号 `1. ` も落とさず、空行も段落の
  区切りとして残す。画像参照の `![]()` の行だけは、読み上げには不要なので除く。
- 本文が無い見出しだけのスライドは、ノートも空になる。

PowerPoint・Keynote・Google スライドのいずれもノート欄として読み込む。
Canva に取り込む場合も、PPTX をUIからインポートすればメモ欄に入る。

## デザインテンプレート

新規プロジェクト作成時に選ぶ「デザインプロンプト」の雛形。
プロンプト文・見本デザイン画像・右下のロゴ用余白設定の3点セットで、
生成するスライドの見た目を決める。

### 編集したプロンプトをその場でテンプレートにする

新規プロジェクト作成の画面で、雛形を選んでプロンプトを書き換えたあと、
テキストエリア下の「これをテンプレートとする」ボタンから登録する。
スライドを生成する前でも保存できる。

1. 見本デザイン画像は、下の「見本デザイン画像」で画像を選べばそれを、
   選んでいなければ元にした雛形の見本画像を引き継ぐ
2. 右下のロゴ用余白設定も元の雛形から引き継がれる
3. 保存後はそのテンプレートが選択された状態になり、そのまま作成に進める

自作テンプレートを編集した場合は、テンプレート名にその名前が初期値で入るので、
そのまま OK すれば上書き更新になる（組み込みテンプレートは上書きできない）。

### 気に入ったスライドをテンプレートにする

ペイン3で生成できたスライドの「テンプレ保存」ボタンから登録する。

1. そのスライドの PNG が**見本デザイン画像**になる
2. プロジェクトのデザインプロンプトが引き継がれる（保存前に編集できる）
3. 右下のロゴ用余白設定も引き継がれる

以後、新規プロジェクトのプルダウンに「（自作）」付きで並び、
組み込みテンプレートと同じように選べる。不要になったらプルダウン横の
「削除」で消せる（そのテンプレートで作った既存プロジェクトには影響しない）。

保存先は `OUTPUT_ROOT/_slide_templates/<テンプレート名>/`。

| ファイル | 内容 |
|----------|------|
| `prompt.txt` | デザインプロンプト |
| `reference.png` | 見本デザイン画像（元になったスライド） |
| `config.json` | 右下ネガティブスペースなどの設定 |

フォルダごとコピーすれば別マシンにも移せる。逆に、ここに同じ3ファイルを
手で置いてもテンプレートとして認識される。

### 組み込みテンプレートを増やす場合

コードに手を入れる方法。`app/slides.py` の以下を編集する。

| 対象 | 役割 |
|------|------|
| `_PROMPT_TEMPLATES_BASE` | プロンプト文（必須） |
| `TEMPLATE_REFERENCES` ＋ `app/template_assets/` の PNG | 見本デザイン画像（任意） |
| `TEMPLATE_NEGATIVE_SPACE` | 右下のロゴ用余白（任意） |

`REFERENCE_TEXT_RULE`（見本画像の文字を流用させない厳守ルール）は
全組み込みテンプレートに自動で付与される。

## セットアップ

```bash
cd ~/src/AI-presentation-tool
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env   # OPENAI_API_KEY などを設定
```

`.env` の主な項目:

| 変数 | 説明 |
|------|------|
| `OPENAI_API_KEY` | OpenAI APIキー |
| `SLIDE_IMAGE_MODEL` | 画像生成モデル（既定 `gpt-image-2`） |
| `SLIDE_TEXT_MODEL` | 本文要約に使うテキストモデル（既定 `gpt-6-astra`） |
| `SLIDE_TEXT_EFFORT` | 要約時の推論の深さ（既定 `low`。`minimal` / `none` は `gpt-6-astra` が非対応なので `low` に丸められる） |
| `OUTPUT_ROOT` | 出力先ルート（既定 iCloud Drive の `Downloads`） |

## 起動

```bash
./start.sh
# または
.venv/bin/python run.py
```

→ http://localhost:5070

出力は `OUTPUT_ROOT/<プロジェクト名>/` に保存される。

| ファイル | 内容 |
|----------|------|
| `markdown.md` | 台本（ドキュメント取り込み結果もここに入る） |
| `_doc/img_NNN.png` | ドキュメントから取り込んだ画像 |
| `plan.json` | 構成案（見出し・本文・キーワード・図解指示・画像参照・ノート用の台本原文） |
| `slide_NN.png` | 生成されたスライド画像 |
| `slide_NN_mat_KK.png` | 手動で追加した素材画像 |
| `<プロジェクト名>.pptx` | 書き出した PPTX |

## 重要な運用上の注意（macOS）

出力先が iCloud Drive のため、**サーバーは単一プロセスで起動する必要がある**
（`run.py` は `debug=False, use_reloader=False`）。
LaunchAgent/launchd 経由で起動すると macOS の TCC 権限継承が切れて
iCloud にアクセスできなくなる。Automator アプリやターミナル（フルディスクアクセス付与済み）
の子プロセスとして起動すること。詳細は `docs/MIGRATION.md` 参照。
